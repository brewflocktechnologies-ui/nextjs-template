## Deviations

1. **Validator.** The spec names `TypeCompiler`. `validateTheme` uses TypeBox's `Value` API, which interprets the schema and needs no `eval`, so it runs under the dashboard's CSP. A compiled validator can be added server-side later. The contract's THEME-11 notes record this.
2. **No `fonts.ts`.** Font stacks already live in the design tokens' `SCALES.fontStacks`; a second table would drift.
3. **ADR-004 status.** T14 says Accepted. Agents never set Accepted (AGENTS.md), so the status reads Proposed with the PoC-C result until the product owner accepts P1.3.
4. **Extra entry `./resolve`.** Added beside `./guard` so the frame can resolve without TypeBox. The size test bundles with Vite (Rolldown) rather than esbuild, which the repository does not depend on directly.
5. **Extra token.** `semantic.elevation.surface` was added to the design tokens so the resolver can apply the tenant's elevation choice.
6. **Fixture change.** Initech light `onAccent` changed from `#082f49` to `#020617`: the old pair was 3.77:1 against the accent, below the D-20 rule. `validation/tenant-fixtures.md` is updated.
7. **Guard hardening.** The guard rejects `__proto__`, `constructor` and `prototype` keys at any depth; the spec only required rejecting the malicious fixtures.
8. **Prettier exclusions (D-23).** `libs/theme/schema/` and `validation/widget-fixtures/` are generated and excluded from formatting, like the token outputs.
