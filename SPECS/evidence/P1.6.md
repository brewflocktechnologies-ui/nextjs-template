## Deviations

1. **No CSP header yet.** The proxy adds the nonce request header and `Cache-Control` only, as T-03 says ("sets nothing else"). The nonce is on the theme `<style>`, ready for a dashboard CSP in P1.7.
2. **`Cache-Control` in development.** `next dev` always sends `no-store` for pages and overrides the proxy and `next.config` headers. Production sends Next's `private, no-cache, no-store, max-age=0, must-revalidate` for dynamic pages. The test asserts `no-store` on pages and the exact `private, no-store` on APIs.
3. **More route handlers.** Besides `POST /api/theme/resolve`: `draft`, `publish`, `rollback`, `revisions` and `POST /api/widget/origins`. Each takes the tenant from the request context and answers 401 without one. **Publish** saves the draft first, then publishes it.
4. **Preview variables.** `theme.preview` sends every resolved variable except `--sem-elevation-surface`: BRIDGE-02's value grammar has no shadows, and the frame does not use elevation.
5. **`ThemeStyleTag` gained `darkVars`** (ui-react) for the `system` dark block, with a unit test.
6. **Dashboard fonts.** `scripts/vendor-fonts.mjs` copies the widget's vendored woff2 files to `public/fonts`; `global.css` declares them. Without this the font would not change between tenants.
7. **Rules folder name.** `tools/eslint-byteflock`, not `tools/eslint-rules`: Nx treats a folder named `tools/eslint-rules` as its own workspace-rules convention and fails without a `tsconfig.json` there.
8. **No pre-commit hook.** There is no hook tooling in the repository; `check-no-local-publish` runs in `pnpm policy:check` and therefore in `pnpm verify`.
9. **E2E production server.** `next build <dir>` run from the workspace root fails to prerender `/_global-error` (`useContext` of null); built from the app folder, as the Nx target does, it works. The e2e server builds into `.next-e2e-prod` (`NEXT_DIST_DIR`) so it cannot wipe a running dev server, starts first, and restores the committed `next-env.d.ts` that the build rewrites.
10. **Development-server timing.** On a cold `next dev`, a page's first load can be replaced by a development reload, and occasionally never hydrates without any browser error. The editor tests warm the pages first, wait for a `data-hydrated` marker on the forms, reload up to twice if needed, and allow 20 s for first API responses. Dashboard tests run one at a time, and `pnpm verify` runs the e2e projects one after another, because the dashboard tests write the widget files the playground suite reads. The ui-react combobox story now waits for the list's closing transition.
11. **Test hook format.** `THEME_FIXTURE_OVERRIDE` maps tenants to fixtures (`t_broken=libs/theme/fixtures/malicious/css-injection-colour.json`) and is set in the committed `apps/admin-dashboard/.env.development`, which also holds the documented development defaults.
12. **Bridge type.** No `libs/widget-contracts` (P1.5-T12); `PreviewFrame.tsx` types the one `theme.preview` envelope locally.
13. **Broken tenant.** `/dev/session` lists `t_broken` (the D-11 broken user) so T-03 and the dev banner can be checked by hand.
14. **`next-env.d.ts` churn.** `next dev` rewrites it to its `.next/dev` types; it is restored to the committed version before committing, as before.
