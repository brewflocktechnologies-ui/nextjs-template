## Deviations and findings

- **`nx add` fails here.** It ended with a pnpm store error, so plugins were added with `pnpm add -D -w @nx/<plugin>@24.0.0` and `pnpm nx g @nx/<plugin>:init`. AGENTS.md records the workaround.
- **Generators needed corrections.**
  - They set `nx.name` to short names, which were removed so project names equal package names.
  - They gave the JS libraries `nodenext` module resolution, replaced by the workspace's `bundler` resolution with extensionless imports (D-07).
  - They put Playwright specs where Vitest and the Playwright lint rules would also pick them up; both were scoped.
- **`headers.config.ts` lives in `apps/widget/src/`**, not at the project root as the spec said, because it must sit inside the TypeScript `rootDir`. Spec references were updated.
- **Widget origin uses Vite `appType: 'mpa'`.** Without it, unknown paths returned the index page with HTTP 200, so the first `stack:check` wrongly reported the loader and config as up. The dev plugin now also serves directory index pages, and `stack:check` verifies content types.
- **Playwright web servers call Vite and `next dev` directly** instead of `nx run …:dev`. Otherwise Nx starts a second dev server, which collides with `pnpm stack` on the strict ports.
- **`check-adr-immutability` also compares with HEAD.** Local `main` predates the ADRs, so comparing with it alone checked nothing while CI is deferred.
- **Theme → ui-react negative test** reports a circular dependency rather than a tag violation, because `ui-react` already depends on `theme`. The tag constraint itself is demonstrated by the widget → ui-react case.
- **Install scripts:** all four packages with scripts are denied in `allowBuilds`, and every target passes without them.
- **Spec corrections:** the runbook's expected `widget` edges are `chat-widget` and `theme`, since `nx graph` lists direct edges only. `stack:books` is marked as arriving with the Storybooks.
- **Process note:** stopping `pnpm stack` from a tool left the three dev servers running on Windows; they were stopped by PID. Ctrl+C in a terminal stops them normally. The developer guide explains how to find a leftover server.
- **Incident, no damage:** one documentation edit was passed through a shell with unescaped backticks, and the shell tried to run fragments as commands. `git status` was clean afterwards, no dev server was left running, and the only commands that executed were a frozen `pnpm install` (no change), an aborted `pnpm stack`, and two that failed immediately. Later edits used the Write tool.
