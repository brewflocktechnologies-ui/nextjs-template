# P2.5 — Onboard the real design systems

|            |                                                                                      |
| ---------- | ------------------------------------------------------------------------------------ |
| Status     | see `STATUS.md`                                                                      |
| Depends on | P2.4 `Accepted`; Design Token Kit exports of the four tenant design systems provided |

| ARCH-001   | §7                                                                                   |
| Contracts  | `contracts/platform-semantic-v1.md`                                                  |
| ADRs       | None                                                                                 |
| Effort     | About 1 week, depending on the exports                                               |

## 1. Goal

The four tenant design systems (and the platform default from Figma, if it differs from `libs/design-tokens/tokens`) are registered repository themes: their exports committed unchanged, each with a reviewed manifest, passing G1–G8, with every lossy conversion approved.

## 2. Preconditions

1. `STATUS.md`: P2.4 `Accepted`, P2.5 `Approved`.
2. The exports, anonymised if needed, are available.

## 3. Scope

**In:** recording the real export shape; adapter fixes it requires; one folder and manifest per design system; contrast results; approvals of mappings and conversions.

**Out:** registry and assignment (P2.6); runtime (P2.8, P2.9).

## 4. Decisions applied

D-30. Theme ids are stable, lower-case and never reused (`^[a-z][a-z0-9-]{1,40}$`).

## 5. Tasks

| ID       | Task                                                                                                                 | Where                                  | Done when                                                        |
| -------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------- |
| P2.5-T01 | Record each export's shape: files, mode overlays, `$extensions`, colour serialisation, units, typography and shadows | Evidence                               | Shape documented; the provisional fixture replaced by a real one |
| P2.5-T02 | Adapter changes the real exports need, each with a fixture                                                           | `libs/theme/src/generate/`             | Fixtures pass                                                    |
| P2.5-T03 | One folder per design system: exports unchanged, manifest with `semanticMap`, fonts registered if new                | `libs/design-tokens/themes/<themeId>/` | G1–G8 pass per theme                                             |
| P2.5-T04 | Contrast and lossy-conversion review with the owner                                                                  | Evidence                               | Every finding fixed in Figma or approved                         |

## 6. Acceptance criteria

| ID        | Criterion                                                                                | Level       |
| --------- | ---------------------------------------------------------------------------------------- | ----------- |
| P2.5-AC01 | Every registered theme passes G1–G8                                                      | `[auto]`    |
| P2.5-AC02 | Export files are committed byte for byte as exported                                     | `[auto]`    |
| P2.5-AC03 | Each theme's `preview.css`, applied in Storybook, matches its Figma frames in both modes | `[manual]`  |
| P2.5-AC04 | The number of manual mapping decisions per theme is recorded                             | `[measure]` |

## 7. Quality gates introduced

None new; the themes join G1–G8.

## 8. Verification procedure (agent)

1. `pnpm nx run @byteflock/design-tokens:verify` → green for all themes.
2. `pnpm verify --quick` → green.

## 9. Manual validation (human)

Compare each theme's preview with its Figma file in light and dark.

## 10. Evidence to record

Export shapes; mapping decisions; approvals with names and dates; deviations.

## 11. Exit and approval

P2.5 → `Accepted` by the product owner.
