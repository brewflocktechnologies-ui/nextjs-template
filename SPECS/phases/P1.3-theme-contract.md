## 1. Goal

Author the tenant theme contract once, in code, and emit everything else from it: JSON Schema 2020-12 for the backend, TypeScript types, a pure resolver to `--sem-*` variables, a small shape guard for the frame, publish-time contrast policy, migrations scaffold, and the fixture set that every later phase tests against. Replace PoC-A's stubs with validated tenant documents.

## 2. Preconditions

- P1.2 accepted (`@byteflock/design-tokens` exports `SCALES`, `SEMANTIC_VARIABLE_NAMES`).
- `libs/theme` shell exists.

## 3. Scope

**In:** PoC-C; schema source; emit + diff target; types; `resolveTheme`; `isSupportedTheme`; `checkContrastPolicy`; `migrate`; fixtures; `validation/tenants.json`; regenerated widget stubs; tests; CI gates; ADR-004.
**Out:** the editor UI (P1.6), the publish stub (P1.6), consuming the resolver in the frame (P1.5) or React (P1.4).

## 4. Decisions applied

Q-002, Q-003, Q-004, Q-010 defaults; D-11. Fixed by this spec: the theme library's only workspace dependency is `@byteflock/design-tokens`; its only runtime third-party dependency is the schema library chosen by PoC-C (`@sinclair/typebox` 0.34.x or `zod` 4.x). `ajv` (2020 build) is a **dev** dependency used only in tests for interoperability.

Contract-diff gate (ARCH-001 §15.3) is added now as a policy script: changes to `libs/theme/schema/theme.v1.json` in a PR require `CONTRACT-CHANGE:` in the PR body (`tools/scripts/policy/check-contract-change.mjs`, reads `GITHUB_EVENT_PATH`; skipped locally with a notice).

## 8. Verification procedure (agent)

1. `pnpm nx run @byteflock/theme:build:check` → 0. Edit `theme.v1.ts` (change `brand.name` max to 61), run again → non-zero; revert.
2. `pnpm nx test @byteflock/theme` → green; print count; grep output for `P1.3-AC0` test titles → AC02–AC09 present.
3. `node -e "..."` or `pnpm exec esbuild libs/theme/src/guard-entry.ts --bundle --minify --format=esm | gzip -c | wc -c` → ≤ 4096; `grep -c typebox` on the bundle → 0 (or `zod`).
4. `pnpm stack:reset && git status --porcelain apps/widget/public validation/widget-fixtures` → empty.
5. `pnpm nx e2e @byteflock/widget-playground --project=chromium` → green.
6. `cat docs/adr/ADR-004-*.md | grep -E "^Status"` → `Accepted`.

## 12. Risks and notes

- TypeBox `Type.String({ pattern })` emits `pattern` in the schema; Ajv 2020 interprets patterns as ECMA-262 by default (`unicodeRegExp: true`), matching TypeBox. Keep patterns simple (no lookbehind).
- The Java backend will validate `theme.v1.json` with its own 2020-12 validator; the Ajv cross-check is the Phase-1 stand-in for that interoperability.
- Do not let `theme` import `lit`, `react` or `next` (lint enforces); it is `platform:neutral`.
- If PoC-C picks Zod, the "schema-first" sentence in ADR-004 becomes "code-first with emitted schema as the contract"; the CI diff gate makes drift impossible either way.
