## 1. Goal

Every registered theme is previewed and verified in light and dark automatically; visual approval is recorded; the duplicate `theme.v1` runtime path is retired.

## 2. Preconditions

`STATUS.md`: P2.8 and P2.9 `Accepted`, P2.10 `Approved`; `pnpm verify` → green.

## 3. Scope

**In:** Storybook theme switcher over registered artifacts (`ui-react`, `chat-widget`); per-theme snapshot set (small set per pull request, full matrix nightly); lint rule stopping shared components from reading `--ext-*`; report section per theme; retiring `resolveTheme(theme.v1)` at runtime and old config fields; dropping the old theme tables in a new migration only after evidence is accepted.

**Out:** new contract tokens.

## 4. Decisions applied

D-26 (gates added once in `verify.mjs`), D-30.

## 7. Quality gates introduced

G1–G11 complete; nightly per-theme visual matrix.

## 8. Verification procedure (agent)

1. `pnpm verify` and `pnpm verify --profile=visual` → green.
2. Add a fixture theme in a scratch branch → appears in previews and gates without other changes.

## 9. Manual validation (human)

Review every theme in Storybook in both modes; record approval.

## 10. Evidence to record

Final verification report across all themes; deviations.

## 11. Exit and approval

P2.10 → `Accepted` by the product owner.
