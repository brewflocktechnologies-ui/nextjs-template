## 1. Goal

A platform-neutral generator turns a theme (DTCG sources plus a manifest) into an immutable, deterministic artifact of `--sem-*` values for light and dark, with a report of every conversion. Proven first on the platform default: expressed as theme `platform-default`, it reproduces today's values exactly. No runtime reads artifacts yet.

## 2. Preconditions

1. `STATUS.md`: P2.4 `Approved`.
2. `pnpm verify --quick` → green.

## 3. Scope

**In:** machine-readable contract, manifest and artifact schemas; the generator (`libs/theme/src/generate/`, own package entry); Nx scripts and targets on `@byteflock/design-tokens`; the `platform-default` theme; the fixture matrix; gates G1–G8.

**Out:** real tenant design systems (P2.5); registry and database (P2.6); upload (P2.7); dashboard and widget changes (P2.8, P2.9); Storybook previews (P2.10).

## 4. Decisions applied

D-30; SEM-01…09. Fixed here:

1. The generator has no file-system, DOM or network dependency; Nx scripts do the file work.
2. The generator entry is `@byteflock/theme/generate`; the frame bundle never contains it.
3. Output is canonical JSON (sorted keys, no time stamps). Re-running on unchanged inputs changes no byte.

## 6. Acceptance criteria

| ID        | Criterion                                                                                                                      | Level    |
| --------- | ------------------------------------------------------------------------------------------------------------------------------ | -------- |
| P2.4-AC01 | `platform-default` regenerates every `--sem-*` value of today's `semantic.css` exactly, in both modes                          | `[auto]` |
| P2.4-AC02 | Regenerating any theme twice, or with shuffled file order, gives byte-identical output                                         | `[auto]` |
| P2.4-AC03 | Every malicious fixture is refused before serialisation; no artifact value contains a forbidden sequence                       | `[auto]` |
| P2.4-AC04 | Unresolved and cyclic references, missing required tokens, opaque-colour violations and unknown fonts fail with the path named | `[auto]` |
| P2.4-AC05 | Every out-of-sRGB conversion appears in the report with original and converted values; nothing is converted without an entry   | `[auto]` |
| P2.4-AC06 | Extensions outside `--ext-<themeId>-*`, or shadowing `--sem-*`, fail                                                           | `[auto]` |
| P2.4-AC07 | The widget frame bundle does not contain `@byteflock/theme/generate`                                                           | `[auto]` |
| P2.4-AC08 | `--themeId` runs one theme; without it every registered theme runs                                                             | `[auto]` |

## 7. Quality gates introduced

G1–G8 (`docs/architecture/design-tokens/design-token-target-architecture.md` §8) in `pnpm verify`.

## 8. Verification procedure (agent)

1. `pnpm nx run-many -t lint typecheck test -p @byteflock/theme @byteflock/design-tokens` → green.
2. `pnpm nx run @byteflock/design-tokens:verify` → green; `compare` reports no difference.
3. `pnpm nx build @byteflock/widget`, then search the frame bundle for a symbol only the generator defines → not found.
4. `pnpm verify --quick` → green.

## 9. Manual validation (human)

Read `report.md` for `platform-default` and one fixture with lossy conversions; confirm they read clearly.

## 10. Evidence to record

Fixture list with results; equivalence output; the colour-conversion choice and its dependency sentence; test count and coverage; deviations.

## 11. Exit and approval

P2.4 → `Accepted` by the product owner.
