## 1. Goal

Themes, immutable approved versions, uploaded sources and tenant assignments live in Postgres. Today's tenant themes are migrated unchanged into tenant-owned themes. Platform admins approve versions and assign them; several tenants can share one.

## 2. Preconditions

1. `STATUS.md`: P2.4 and P2.1 `Accepted`, P2.6 `Approved`.
2. `pnpm db:up`, `pnpm verify --quick` → green.

## 3. Scope

**In:** migration `0002_theme_registry.sql`; platform data functions; repository-theme sync (`pnpm db:sync-themes`); migration of `theme_revisions`; materialisation of `/v1/themes/<themeId>/<version>.json` and config fields `themeId`, `version`; platform UI to approve and assign; G11.

**Out:** upload (P2.7); dashboard and widget reading artifacts (P2.8, P2.9). Old tables are not dropped (P2.10).

## 4. Decisions applied

D-24, D-25, D-30; ADR-015. Fixed here:

1. Only approved versions can be assigned (constraint). Approved versions are immutable (trigger, as for `theme_revisions`).
2. `themes` and `theme_versions` join the `check-db-safety` allowlist with reasons; `tenant_theme_assignments` has forced RLS.
3. The sync refuses a repository version whose committed artifact differs from a fresh generation.

## 6. Acceptance criteria

| ID        | Criterion                                                                                      | Level      |
| --------- | ---------------------------------------------------------------------------------------------- | ---------- |
| P2.6-AC01 | An unapproved version cannot be assigned; an approved version cannot be changed                | `[auto]`   |
| P2.6-AC02 | Two tenants share one theme version; each sees only its own assignment and owner themes        | `[auto]`   |
| P2.6-AC03 | Every migrated version is byte-identical to its source revision                                | `[auto]`   |
| P2.6-AC04 | Rolling back re-activates the previous assignment and rewrites the config pointer              | `[auto]`   |
| P2.6-AC05 | The approval record holds reviewer, date and notes                                             | `[auto]`   |
| P2.6-AC06 | The migration dry-run report is reviewed before the migration is applied to the stack database | `[manual]` |

## 7. Quality gates introduced

G11; RLS isolation with a shared theme joins `check-db-safety` and the isolation tests.

## 8. Verification procedure (agent)

3. `pnpm verify --quick` → green.

## 9. Manual validation (human)

Approve a version, assign it to two tenants, roll one back.
