## 1. Goal

Turn the PoC-B components into the `ui-react` foundation: generated Tailwind bridge from tokens, a React theme adapter that consumes `resolveTheme()` output, the Phase-1 component set with stories that are both spec and test, tenant theme fixtures in Storybook, and accessibility gates that block merges.

## 2. Preconditions

- `@byteflock/theme` exports `resolveTheme`, fixtures and `RESOLVED_KEYS`; `@byteflock/design-tokens` exports `semantic.css` and `SCALES`.
- PoC-B's Storybook, Tailwind and shadcn setup exist under `libs/ui-react`.

## 3. Scope

**In:** `shadcn-bridge.css` generator, CSS entry convention, `ThemeStyleTag`/`useTheme`, components of §11.3, one composite, Storybook theme toolbar with the tenant trio, Vitest interaction tests, axe blocking, ADR-008 notes, library README.
**Out:** dashboard integration (P1.6), the `qk()` query-key helper and `QueryClient` setup (P1.6), visual regression (P1.7).

## 4. Decisions applied

ADR-006 outcome (Base UI unless PoC-B chose Radix). Fixed by this spec:

- `shadcn-bridge.css` is **generated** by `libs/ui-react/scripts/generate-bridge.mjs` from `@byteflock/design-tokens` `SEMANTIC_VARIABLE_NAMES` and a committed mapping table `src/theme/shadcn-map.json` (`--background` → `--sem-color-surface`, `--foreground` → `--sem-color-on-surface`, `--primary` → `--sem-color-primary`, `--primary-foreground` → `--sem-color-on-primary`, `--accent` → `--sem-color-accent`, `--destructive` → `--sem-color-danger`, `--ring` → `--sem-color-focus-ring`, `--border` → `--sem-color-outline`, `--radius` → `--sem-radius-md`, …). Output committed; stale check in CI (same pattern as tokens).
- CSS entry convention for every React app: `@import "tailwindcss"; @import "@byteflock/design-tokens/css/semantic.css"; @import "@byteflock/ui-react/shadcn-bridge.css"; @source "../../../libs/ui-react/src";` — documented, used by Storybook now and by the dashboard in P1.6.
- `ThemeStyleTag({ vars, nonce, scope?: 'all' | 'brand' })` renders one `<style nonce>` with `:root{…}` from a `ResolvedVars` map; it never accepts raw theme documents. `useTheme()` returns the vars from a `ThemeProvider` context; the provider is given already-resolved vars by the server.

## 7. Quality gates introduced

Merge-blocking from P1.4 (§14.2 row 4, React): `ui-react:build-storybook`, `ui-react:test-storybook` (interaction + axe serious/critical), `ui-react:build:check`.

## 8. Verification procedure (agent)

1. `pnpm nx run-many -t build:check -p @byteflock/design-tokens @byteflock/theme @byteflock/ui-react` → green.
2. `pnpm nx run @byteflock/ui-react:test-storybook` → green; count ≥ 12 stories tested; a11y summary shows 0 serious/critical.
3. `pnpm nx run @byteflock/ui-react:test-storybook -- --grep a11y-negative` with the tag enabled → fails with an axe violation (record), then disabled again.
4. `ls libs/ui-react/src/poc libs/ui-react/.storybook/poc.css` → both missing.
5. `pnpm nx lint @byteflock/ui-react` → clean; negative import test for `lit` fails lint; revert.
6. `pnpm nx run @byteflock/ui-react:storybook` → runbook steps at `http://localhost:4600`.

## 9. Manual validation (human)

`validation/manual-validation-runbook.md` → P1.4.

## 10. Evidence to record

Story/test counts; a11y summary; bridge mapping table size; dependency sentences (`@tanstack/react-table`, any new addon); Storybook build time.

## 11. Exit and approval

P1.4 → `Accepted`. P1.6 eligible when P1.5 is also accepted.

## 12. Risks and notes

- Tailwind v4's `@source` must point at the library source from each consuming app's CSS entry; the dashboard (P1.6) copies the convention verbatim. A sync generator is added only if drift occurs (ARCH-001 §11.2).
- Keep shadcn-generated files unmodified where possible so `shadcn diff` stays useful; wrappers live beside them.
- `ThemeStyleTag` throwing on bad keys is intentional: in P1.6 the dashboard wraps it so a bad stored theme falls back to defaults at the data layer, never at render.
