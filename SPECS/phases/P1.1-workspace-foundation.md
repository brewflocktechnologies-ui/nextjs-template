## 1. Goal

Convert the template into the day-one workspace of ARCH-001 §6.1 on top of the existing Nx setup: pnpm 11 with supply-chain settings, the eight projects with tags and enforced boundaries, Vitest for libraries, the local-stack scripts, and CI on Linux and Windows. At exit, `nx graph` shows exactly the eight projects and every gate of ARCH-001 §14.2 row 1 is merge-blocking.

## 2. Preconditions

```bash
node --version        # v24.x
corepack --version    # present
npx nx show projects  # @nextjs-template/web, @nextjs-template/web-e2e, @nextjs-template/ui
npm run policy:check  # exit 0 (P1.0)
```

`STATUS.md`: P1.0 `Accepted`, P1.1 `Approved`, D-02 = migrate (otherwise follow the npm variant noted in §12), D-06 answered (scope below written as `@byteflock`; substitute).

## 3. Scope

**In:** package manager migration; renames and deletions of template content; generation of the five new projects as empty-but-wired shells (each builds, lints, tests with one placeholder test, and has its `package.json` exports and tags); boundary rules; Vitest; local-stack scripts; CI matrix; `nx sync:check`; ADR verification sections.
**Out:** any feature code (tokens, schema, loader, components); Storybook (P1.4/P1.5 add it); Tailwind (P1.4); Lit elements beyond a placeholder export (PoC-A/P1.5). The widget dev plugin only applies headers in P1.1; failure fixtures come in PoC-A.

## 4. Decisions applied

D-01…D-07, D-10, D-16, D-17, D-19. Fixed by this spec:

- **Unit test runners:** `admin-dashboard` keeps Jest via `next/jest` (template wiring, D-04 rationale); every other project uses Vitest (`@nx/vitest` plugin, inferred `test` target). ARCH-001 §12 names Vitest for units; the dashboard exception is recorded in ADR-008's notes.
- **Vite app generator:** `@nx/web:application --bundler=vite` for `widget` and `widget-playground` (vanilla TS, no framework).
- **Library generators:** `@nx/js:library --bundler=none --unitTestRunner=vitest` for `design-tokens`, `theme`, `chat-widget`; `@nx/react:library --bundler=none --unitTestRunner=vitest --style=css` for `ui-react`. Each library's `package.json` exports `./src/index.ts` (source consumption, D-07).

## 7. Quality gates introduced

Merge-blocking from P1.1 (ARCH-001 §14.2 row 1): format, lint (boundaries + restricted imports), typecheck, `sync:check`, frozen lockfile, SHA-pinned actions, supply-chain settings, project set and tags. Branch protection requires `lint-test-build` and `widget-windows`.

## 8. Verification procedure (agent)

Run from a clean clone (`git clone … tmp && cd tmp`):

1. `corepack enable && pnpm install --frozen-lockfile` → exit 0; output contains no "Ignored build scripts".
2. `pnpm nx show projects` → eight names, sorted, equal to `tools/scripts/expected-projects.json`.
3. `pnpm policy:check` → exit 0.
4. `pnpm nx sync:check` → exit 0.
5. `pnpm nx run-many -t lint test typecheck build` → all succeed.
6. `pnpm nx graph --file=/tmp/graph.json` (Windows: `%TEMP%\graph.json`) then `node tools/scripts/compare-graph.mjs /tmp/graph.json` → "graph matches".
7. Negative lint: `echo "import React from 'react'; export const x = React;" >> libs/chat-widget/src/index.ts && pnpm nx lint @byteflock/chat-widget` → fails with "React/Next must not enter widget bundles"; `git checkout libs/chat-widget`.
8. `pnpm nx run @byteflock/widget:build && grep -rlE "react-dom|__next|next/dist" apps/widget/dist` → no output.
9. In one terminal `pnpm stack`; in another `pnpm stack:check` → three `OK` lines and the five headers.
10. On Windows (the product owner's machine or CI): steps 1, 5, 8 repeated; results pasted.

## 12. Risks and notes

- **If D-02 is overturned (stay on npm):** skip T01/T09's pnpm parts; keep `npm ci`; `check-supply-chain.mjs` instead asserts `.npmrc` `ignore-scripts=true` plus an explicit `scripts-allowlist` handled by a postinstall script; ADR-011 is rewritten. All `pnpm nx` commands in later specs read `npx nx`.
- `@nx/workspace:move` on Windows: run from Git Bash or PowerShell at the repo root; verify `apps/admin-dashboard/tsconfig.json` `include` paths and `jest.config.cts` `coverageDirectory` after the move.
- `strictPort: true` makes port collisions fail fast instead of silently shifting origins (which would break the preview-mode origin pin later).
- Nx 24's `@nx/vitest` plugin infers `test` from `vitest.config.*ts`; do not also add Jest configs to the libs.
- Next's `AGENTS.md` under `apps/admin-dashboard/` reappears on every `dev` run (D-19); commit it once.
