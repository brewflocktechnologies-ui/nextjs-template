## 1. Goal

Create the framework-neutral token source and build: DTCG 2025.10 token files, a pinned Style Dictionary 5 build producing committed CSS variables, TypeScript names and JSON fixtures, with a CI stale check. Everything downstream (`theme` resolver, React bridge, Lit theme controller) binds only to the `--sem-*` names produced here.

## 2. Preconditions

- `libs/design-tokens` exists as a shell (P1.1-T03) with `typecheck`, `lint`, `test` targets.
- No other project yet imports anything but the placeholder from it.

## 3. Scope

**In:** token sources, build config, generated outputs, tests, stale check, enum-to-value scale tables used by the resolver, ADR-003 verification.
**Out:** component tokens (deferred per §7), the DTCG Resolver module (not used), any consumption in apps (P1.4/P1.5), the theme contract (P1.3).

## 4. Decisions applied

ARCH-001 §7 as written. Fixed by this spec:

- Appearance is expressed as **two semantic token sets** (`semantic.light`, `semantic.dark`) built into one CSS file: `:root { … }` (light) and `:root[data-appearance="dark"], [data-appearance="dark"] { … }`.
- Density and type scale are **multiplier/scale sets**, not separate CSS files: `--sem-space-*` carry the `comfortable` values; `--sem-density-factor` and `--sem-type-scale-*` are emitted per set under `[data-density="…"]` and `[data-type-scale="…"]` selectors so the resolver can select by attribute **or** by emitting overridden values. The resolver (P1.3) emits concrete values; the attribute selectors exist for Storybook and docs.
- Style Dictionary version pinned exactly (`"style-dictionary": "5.x.y"`, no caret).

## 8. Verification procedure (agent)

1. `pnpm nx run @byteflock/design-tokens:build && git status --porcelain libs/design-tokens/src/generated` → empty.
2. `pnpm nx run @byteflock/design-tokens:build:check` → exit 0.
3. Edit `tokens/primitives/radius.tokens.json` (`md` 8 → 9), run `build:check` → non-zero; `git checkout libs/design-tokens`.
4. `pnpm nx test @byteflock/design-tokens` → green; print count.
5. `grep -cE "^\s*--sem-" libs/design-tokens/src/generated/css/semantic.css` → ≥ 40; `grep -E "\-\-(blue|neutral)-" libs/design-tokens/src/generated/css/semantic.css` → nothing.
6. `node -e "const p=require('./libs/design-tokens/package.json');console.log(Object.keys(p.dependencies||{}).length)"` → `0`.

## 12. Risks and notes

- Style Dictionary 5's DTCG 2025.10 support is reported partial (ARCH-001 §6.5). If `$extensions` or alias syntax misbehaves, restrict the source to what works and record the subset in ADR-003; do not add a pre-processing step.
- Keep the emitted CSS free of `@media (prefers-color-scheme)`; appearance is driven by `data-appearance`, set by the consumer (dashboard SSR or frame bootstrap), so that `system` mode is handled in one place per consumer.
