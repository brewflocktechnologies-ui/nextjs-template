## 7. Quality gates introduced

Merge-blocking from P1.7 (§14.2 last row): axe moderate, visual regression, contract-diff, dependency-diff, test-count ratchet, telemetry tripwire. Nightly: Firefox/WebKit, Lighthouse (warn → error after two weeks).

## 8. Verification procedure (agent)

1. `pnpm policy:check` → green on `main`.
2. For each new policy script run its documented negative case (delete a test file; edit `protocol.ts`; add a dependency; add `message:` to a beacon payload) → each fails with its message; revert.
3. `gh run list --workflow=nightly.yml --limit 1` → completed.
4. `gh api repos/{owner}/{repo}/branches/main/protection` → required checks include `lint-test-build`, `widget-windows`, `visual`.
5. Fresh clone walkthrough per T06; record minutes.
6. Open `SPECS/evidence/P1-exit.md` → eleven rows with links.

## 9. Manual validation (human)

`validation/manual-validation-runbook.md` → P1.7, then the §14.4 walk with the evidence file.

## 10. Evidence to record

Negative-run outputs; CI timing table; remote-cache decision; onboarding time; retrospective link; exit checklist; signatures.

## 11. Exit and approval

P1.7 → `Accepted`; **P1 exit** → `Accepted`; ARCH-001 v1.0 _Accepted_. Phase 2 planning starts from the retrospective.

## 12. Risks and notes

- Visual snapshots are platform-sensitive; the container-only rule is what keeps Windows development friction-free. Never commit snapshots generated outside the pinned image.
- The test-count ratchet must count by runner and sum; flaky list output (e.g., Playwright `--list` including skipped) should be normalised before comparing.
- Lighthouse numbers on CI runners vary; start as warnings.
