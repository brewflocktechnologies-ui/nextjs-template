## 1. Goal

Prove, with running code and automated fixtures, that the hybrid design (framework-free launcher on the host page, Lit conversation document in a cross-origin iframe, lifecycle-only bridge) delivers confidentiality from host-page scripts, survives hostile CSS and strict CSP with only two directives, works by keyboard and on mobile, and fails safely. Record the measurements that become budgets. The code written here is the real foundation of `apps/widget` and `apps/widget-playground`; P1.5 hardens it rather than rewriting it.

## 2. Preconditions

- P1.1 accepted: `apps/widget` (4400) and `apps/widget-playground` (4300) exist with the headers plugin; `pnpm stack` works.
- `lit` installed in `libs/chat-widget` (P1.1-T03). PoC-A may import `@byteflock/chat-widget` placeholders but builds its own frame shell inside `apps/widget/src/frame/` (P1.5 moves reusable elements into the library).

## 3. Scope

**In:** `loader.ts`, `launcher/`, `frame/` shell (header with brand name, static message list, composer), `bridge/protocol.ts` with validators and limiter, config and theme fetch with a **provisional** theme mapper, dev-server plugin extensions (D-14), static stubs for the tenants, playground fixtures and Playwright tests, measurements, ADR-007 update, `docs/developer-guide/embedding.md` draft.
**Out:** real message transport, consent persistence (P1.5), the `@byteflock/theme` resolver (P1.3; PoC-A uses `frame/provisional-theme.ts`, which P1.5 deletes), Storybook, fonts beyond one curated family (`inter` as a local woff2 under `public/v1/fonts/inter/`), final budgets (P1.5 sets them from these measurements).

## 4. Decisions applied

D-10, D-11 (stubs for `t_acme`, `t_globex`, `t_initech`, `wk_broken_*`, `wk_missing`), D-14, D-15, Q-005 (two instances, test only), Q-014 (answered yes, D-21: PoC-A keeps `frame-ancestors *` and does not build the allowlist; P1.5-T13 does), Q-015 (frame created hidden at idle; on-open strategy also implemented behind `features.proactive=false` for measurement).

Fixed by this spec: the provisional theme mapper reads `color.<mode>.primary/onPrimary/surface/onSurface/accent`, `shape.radius`, `launcher.*`, `brand.name`, `typography.fontFamily` from theme documents shaped per THEME-02, and sets a fixed small set of `--sem-*` variables. It must live in one file with a header comment `PROVISIONAL — replaced by @byteflock/theme in P1.5`.

## 7. Quality gates introduced

`@byteflock/widget-playground:e2e` (Chromium) and `@byteflock/widget:test` run in CI from PoC-A; they become **merge-blocking at P1.5** (ARCH-001 §14.2). The leakage grep in `assert-bundle.mjs` is blocking immediately (it extends P1.1-AC09).

## 8. Verification procedure (agent)

1. `pnpm nx run-many -t test -p @byteflock/widget` → all bridge/loader/launcher unit tests pass; print the test count.
2. `pnpm nx run @byteflock/widget:build` → tree per ENDP-09; `node apps/widget/scripts/assert-bundle.mjs` → "no leakage"; sizes printed.
3. `pnpm nx run @byteflock/widget:preview` in one terminal; `node tools/scripts/stack-check.mjs --preview` → five headers exact (compare with ENDP-03 string, `nonce` wildcarded).
4. `pnpm stack` in one terminal; `pnpm nx e2e @byteflock/widget-playground --project=chromium` → green; `--project=webkit --grep mobile` → green.
5. `pnpm nx e2e @byteflock/widget-playground --grep @measure` → prints the measurement table; compare with `docs/architecture/baselines.md`.
6. `grep -rnE "fetch\(|innerHTML|localStorage|sessionStorage|sendBeacon|XMLHttpRequest|window\.parent" apps/widget/src/launcher apps/widget/src/loader.ts` → no output.
7. `grep -rn "PROVISIONAL" apps/widget/src` → exactly `frame/provisional-theme.ts`.
8. Read `docs/adr/ADR-007-*.md` → status and residuals present.

## 12. Risks and notes

- Vite dev HMR injects `<style>` elements; the strict frame CSP may block them in `dev`. T07 allows a dev-only relaxation and records it. All header assertions run against `preview`.
- `location.ancestorOrigins` is absent in Firefox < 148; the `parent` URL parameter path must be tested by running the Firefox project once locally (record the result; nightly Firefox arrives in P1.7).
- Playwright cannot type into a cross-origin frame's textarea through the parent page; use `page.frameLocator('iframe')` which handles cross-origin frames.
- The hostile-script fixture must try `iframe.contentDocument` and catch the `SecurityError`; the test asserts the error type, not just absence of text.
- Keep the composer a real `<textarea>` so `document.activeElement` on the host page resolves to the `<iframe>` element, never to the text.
