| ID   | Category      | Risk                                                                                                                                  | L   | I   | Mitigation                                                                                                                                                                                     | Owner decision needed      |
| ---- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --- | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| R-01 | Security      | Generated tenant CSS reintroduces injection (T-03) through names, values, descriptions or extensions                                  | M   | H   | Names only from contract and extension grammar; values re-serialised from typed canonical values; malicious-fixture and property tests on every artifact; frame keeps its allow-list and guard | ADR-014                    |
| R-02 | Technical     | Real Design Token Kit exports differ from assumptions (file layout, mode metadata, colour format)                                     | H   | M   | Manifest maps files and modes explicitly; no reliance on file names; first task of implementation reads real exports of all five design systems                                                | Provide exports            |
| R-03 | Technical     | Style Dictionary 5.7.1 has no documented `$ref` JSON Pointer, `$extends` or Resolver support, and Design Token Kit exports use `$ref` | H   | M   | Adapter resolves `$ref` and mode overlays before Style Dictionary sees the tokens; unsupported features reported per token; equivalence test on platform default                               | —                          |
| R-17 | Dependency    | Design Token Kit is young (created 2026-06; majors 2.0 and 3.0 in October 2026); its export shape may change between versions         | H   | M   | Use plugin output as input files only; record `producer.version` in the manifest; fixture per producer version; no CLI or Core dependency                                                      | —                          |
| R-18 | Technical     | Plugin export details are undocumented: `$extensions` mode metadata, colour serialisation, units, typography and shadow shapes        | H   | M   | Manifest maps modes explicitly, so metadata is not required; first implementation task inspects real exports and records their shape                                                           | Provide exports            |
| R-04 | Data loss     | Lossy conversions (alpha flattened, out-of-gamut clamped, units converted) pass unnoticed                                             | M   | H   | Every conversion is a report entry; contract forbids alpha where not allowed instead of flattening; approval required; artifact keeps source hashes                                            | Out-of-gamut policy        |
| R-05 | Data loss     | Information outside the contract (component tokens, typography composites) is dropped                                                 | H   | L   | Sources are kept unchanged in the registry; the report lists everything not emitted; extensions carry what themes need                                                                         | —                          |
| R-06 | Migration     | Moving `theme_revisions` to theme versions breaks published tenants or rollback                                                       | M   | H   | Additive migration; old tables untouched until verified; byte-identical artifact comparison per tenant; reversible pointer                                                                     | —                          |
| R-07 | Compatibility | Widget guard grows past its ≤ 2 KB budget when the allow-list grows                                                                   | M   | M   | Guard checks artifact shape and the allow-list from a constant; bundle budget gate                                                                                                             | Budget exception if needed |
| R-08 | Compatibility | Contract too wide makes designers fill unused tokens; too narrow blocks components                                                    | M   | M   | Required set = what components read; optional with fallback; promotion rule with a deprecation window                                                                                          | —                          |
| R-09 | Security      | Platform-scoped tables weaken tenant isolation                                                                                        | L   | H   | Tenants read only through a scoped function returning their active assignment; RLS on assignments; isolation test with a shared theme                                                          | —                          |
| R-10 | Delivery      | Flash of the wrong theme or theme leakage between tenants in SSR                                                                      | L   | H   | Keep per-request SSR style tag, `force-dynamic`, `private, no-store`; cache keys include tenant, theme version and appearance                                                                  | —                          |
| R-11 | Quality       | Visual snapshot count grows with themes × modes × screens, slowing CI                                                                 | M   | M   | Snapshots per theme on a fixed small screen set; full set nightly                                                                                                                              | —                          |
| R-12 | Governance    | An unapproved theme version gets assigned or published                                                                                | L   | H   | Database constraint: assignments reference approved versions only; approval record with name and date                                                                                          | —                          |
| R-13 | Scope         | Two source channels (repository and upload, both from the start) drift apart or produce different artifacts for the same source       | M   | H   | One platform-neutral generator for both; test that the same source gives byte-identical artifacts by either channel; one source origin per theme; P2.2/P2.3 re-scoped onto the registry (T3b)  | Re-scope P2.2 (T3b)        |
| R-14 | Fonts         | Design systems use fonts outside the curated five; external font URLs would break CSP and THEME-01 rule 4                             | H   | M   | Fonts must be platform-hosted and registered; unknown families fail validation with a clear message                                                                                            | Font list                  |

| R-16 | Assumption    | Shadow DOM inheritance of variables assumed from code, not re-tested                                                                  | L   | M   | G9 Playwright assertion on computed styles inside shadow roots                                                                                                                                 | —                          |
