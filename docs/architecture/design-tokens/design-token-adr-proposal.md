## ADR-014 (draft): Independent design systems as platform-generated themes

**Supersedes:** ADR-004's grammar decision for tenant themes (THEME-01 rule 1 and THEME-02 as the only tenant theme format). ADR-004's lifecycle, immutability, contrast policy and resolver allow-list stay.

### Context

ADR-004 limits tenant themes to 13 colours and enumerated presets, so tenant input can never become CSS (threat T-03). The product now needs five independent Figma design systems (and more later), each with its own primitives, semantic and component tokens, light and dark modes, delivered to the dashboard and the widget, and shareable between tenants.

### Decision drivers

1. Keep T-03's guarantee: no tenant- or file-supplied text ever reaches a stylesheet.
2. Keep shared components unchanged and tenant-agnostic.
3. Support any number of themes without code changes.
4. Preserve DTCG information and report every lossy conversion.

### Options

1. **Platform-generated themes from typed tokens (chosen).** Design systems are DTCG sources. A platform generator validates them, maps them onto the platform semantic contract and serialises every value from its typed canonical form into an artifact of allow-listed variables.
2. **Widen `theme.v1`.** Add typed fields for typography, spacing, shadows. Keeps ADR-004 but cannot hold an independent design system or share it between tenants, and every new field is a schema change.
3. **Accept tenant CSS files.** Simple, but breaks T-03 and gives tenants control over arbitrary selectors.

### Decision outcome

Option 1.

- Variable names come only from the contract (`--sem-*`) and the extension grammar (`--ext-<themeId>-*`), never from input.
- Values are re-serialised by the generator from canonical typed values: colours as hex, dimensions as number plus an allow-listed unit, numbers, shadow layers, font families from the platform registry. No source string is copied into output. The existing resolver tests (no `url(`, `expression(`, `;`, braces, angle brackets, newlines) apply to every artifact.
- Artifacts are immutable, versioned, approved by a human, and assigned to tenants through the registry.
- `theme.v1` remains a supported source format, so editor-authored themes and today's data keep working.

### Consequences

- Good: unlimited themes, sharing between tenants, full design systems, no component changes.
- Bad: a second theme pipeline to maintain until `theme.v1` is only a source format; platform-scoped tables need an RLS exception.
- Neutral: the contract, not the tenant, decides which tokens shared components can use.

### Verification (when implemented)

Malicious-fixture suite extended to DTCG sources (CSS in names, descriptions, values, extensions); property test over random valid tokens; equivalence test (platform default regenerated byte-identically); two-tenant isolation test with a shared theme.

## ADR-015 (draft): Theme registry separate from tenants

### Decision

Themes, immutable theme versions and tenant assignments are separate Postgres tables (contract proposal §3). Themes are platform-scoped; assignments are tenant-scoped with forced RLS. Only approved versions can be assigned. Rollback is a pointer move between assignments.

### Alternatives considered

- Keep `theme_revisions` per tenant and copy shared themes into each tenant: simple, but duplicates sources and breaks "one approval per version".
- Registry as files in the repository only: simple for curated themes, but no runtime assignment without a deploy.

### Consequences

`check-db-safety` gains two allow-listed tables with reasons; the widget config document carries `themeId` and `version`; materialisation writes `/v1/themes/<themeId>/<version>.json`.

## ADR-016 (draft): Generation on Style Dictionary 5 with a thin contract adapter

### Decision

Reuse the pinned Style Dictionary 5.7.1 (ADR-003) for parsing and reference resolution; add a small adapter in `libs/design-tokens/scripts/` that applies the manifest's `semanticMap`, enforces the contract, records lossy conversions and writes the artifact. Design Token Kit is treated as an export tool only: its files are inputs. No Design Token Kit CLI or Core dependency until a real export proves a need.

### Alternatives considered

| Option                                                                    | For                                                                                                                                                                                | Against                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Design Token Kit CLI (`@design-token-kit/cli` 3.2.0, Apache-2.0) directly | One tool from Figma to CSS; supports DTCG 2025.10, `{path}` and `$ref`, cycle detection; CSS and Tailwind v4 outputs                                                               | Emits its own names from token paths (for example `--semantic-color-text-primary`), not the platform contract; Tailwind output is a per-project `@theme` block, which would duplicate the shared mapping (ADR-017); no documented prefix or naming options for CSS; project created 2026-06 with three majors in five months |
| Design Token Kit Core API with an adapter                                 | Reads its own exports natively, including `$ref`                                                                                                                                   | New, fast-moving dependency; the contract adapter is needed anyway                                                                                                                                                                                                                                                           |
| Style Dictionary + adapter (chosen)                                       | Already pinned (5.7.1 has 2025.10 colour objects, dimension objects, shadow `inset`, `$root` fixes); already produces `semantic.css`; deterministic; outputs already stale-checked | No documented `$ref` JSON Pointer or `$extends` support, and no Resolver module (style-dictionary issue #1590): the adapter resolves `$ref` and mode overlays itself                                                                                                                                                         |
| Fully custom parser                                                       | Full control                                                                                                                                                                       | Re-implements reference resolution                                                                                                                                                                                                                                                                                           |

Sources: design-token-kit.github.io (docs: formats/dtcg, figma-plugin/export-formats, cli/convert), registry.npmjs.org (`@design-token-kit/cli`, `@design-token-kit/core`), styledictionary.com/info/dtcg, style-dictionary CHANGELOG and issue #1590, checked 2026-11-14.

## ADR-017 (draft): One shared Tailwind v4 mapping

### Decision

Keep the generated `shadcn-bridge.css` (`@theme inline`) as the only utility mapping. It references `--sem-*` only. Tenant artifacts never contain `@theme` or utility classes. A new utility requires a contract token first.

### Consequence

Onboarding a theme never touches Tailwind. The widget keeps plain Lit styles reading `--sem-*`.

## Owner decisions (2026-11-14)

1. **Architecture approved** as the basis for T0, including drafting ADR-014 to supersede ADR-004's tenant-grammar decision. ADR-014 to ADR-017 still go into `docs/adr/` as `Proposed` and become binding only when the owner accepts them.
2. **Theme sources: both channels from the start.** Curated design systems live in the repository (`libs/design-tokens/themes/<themeId>/`, reviewed by pull request); tenant uploads through the dashboard are stored in Postgres. Each theme has exactly one source origin, recorded on the theme, so no source exists in two places.
3. **Tenant admins keep the theme editor.** Publishing from the editor creates a new version of the tenant's own theme (`source.format: "theme-v1"`), through the same gates and approval.
4. **Fonts: a platform font registry.** New families may be added, but only self-hosted by the platform; unknown families fail validation.
5. **Out-of-sRGB colours: convert, report, require approval.** The report shows original and converted values; a version with such conversions cannot be approved without accepting them.

### Consequence of decision 2 for ADR-016

Because uploads are generated by the dashboard server and curated themes by an Nx target, both must use **one** generator, or the two channels could produce different artifacts for the same source. The generator and contract adapter are therefore a platform-neutral TypeScript module in `libs/theme` (no file system, no DOM), called by a thin Nx script for the repository and by the dashboard server for uploads. Style Dictionary 5.7.1 stays where ADR-003 put it, building the platform default, and is used in T1's equivalence test as the reference. Colour-space conversion (for decision 5) needs a colour library or a small, tested implementation; the choice and its dependency sentence are part of T1.
